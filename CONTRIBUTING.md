# Contributing

1. Read AGENTS.md, INSTALL.md, and the README for the component you are changing.
2. Create a focused branch and keep changes scoped to one behavior.
3. Add tests for changed behavior. Prefer deterministic unit tests and mock external services.
4. Run the relevant Python tests and frontend checks before opening a pull request.
5. Preserve the project MIT license and all third-party notices.
6. Never include secrets, user data, runtime databases, browser profiles, or machine-specific paths.

For bugs, include the operating system version, Python/Node versions, the component affected, reproduction steps, and sanitized logs. Remove tokens, email addresses, file contents, and other private data before sharing logs.
